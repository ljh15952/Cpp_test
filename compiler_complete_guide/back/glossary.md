# 용어집(Glossary)

용어는 본문에서 사용한 의미를 기준으로 정의한다. 영어 약어는 첫 등장 장의 문맥과 함께 확인한다.

## 5,000줄급 컴파일러의 저장소 설계

중간 규모 교육용 컴파일러는 기능보다 의존 방향이 품질을 좌우한다. diagnostics와 source는 하위 계층, AST와 types는 중앙, parser·semantic·backend는 상위, CLI는 조정 계층으로 둔다. **관련 장:** 55장, 59장, 61장.

## ARM/AArch64의 load-store 설계

AArch64는 고정 32비트 명령, 31개 범용 레지스터, load-store 구조, 조건 분기와 일부 조건 선택 명령을 제공한다. 주소 생성과 메모리 접근이 명시적으로 분리된다. **관련 장:** 43장, 44장.

## AST 불변식과 노드 소유권

AST는 Parser의 임시 결과가 아니라 이후 모든 패스가 신뢰하는 계약이다. 필수 자식의 존재, 노드 종류별 타입 필드, 범위 포함 관계, 선언과 참조의 연결 시점을 명시한다. **관련 장:** 20장, 23장, 24장, 25장, 51장, 64장.

## AST 직렬화와 구조 테스트

AST 테스트는 포인터 주소나 내부 컨테이너 순서가 아니라 의미 구조를 안정적인 텍스트 또는 JSON으로 표현해 비교해야 한다. S-expression은 작고 diff가 읽기 쉽다. **관련 장:** 24장, 25장, 56장.

## CST와 AST의 정보 선택

Concrete Syntax Tree는 괄호, 구분자, 문법용 비단말처럼 원문 구조를 보존하고, Abstract Syntax Tree는 의미 처리에 필요한 노드만 남긴다. 어느 정보가 ‘불필요’한지는 컴파일러, 포매터, IDE의 목적에 따라 달라진다. **관련 장:** 23장, 24장.

## Clang 드라이버와 프런트엔드 도구

Clang 드라이버는 전처리, cc1 프런트엔드, LLVM 코드 생성, 어셈블, 링크 단계를 조정한다. `-###`와 `-save-temps`는 실제 명령과 중간 산출물을 드러낸다. **관련 장:** 46장.

## Clang, MSVC, TinyCC의 설계 지향점

Clang은 라이브러리화된 C 계열 프런트엔드와 진단·도구 API를, MSVC는 Windows 개발 환경·ABI·디버거와의 강한 통합을, TinyCC는 매우 빠른 단일 패스에 가까운 컴파일과 작은 크기를 우선한다. **관련 장:** 4장.

## C·C++·Rust·Go·Python 구현 언어 비교

컴파일러 구현 언어 선택은 성능만이 아니라 메모리 모델, 합 타입, 빌드·배포, 라이브러리, 팀 역량, 플러그인 ABI를 함께 고려한다. **관련 장:** 63장, 67장.

## C로 구현하는 수동 Lexer

C Lexer는 포인터 산술, 명시적 버퍼 수명, 태그 열거형을 사용해 매우 낮은 오버헤드로 토큰을 만든다. 동시에 경계 초과와 정수 변환 오류를 직접 통제해야 한다. **관련 장:** 14장, 16장, 64장.

## DFA 최소화와 상태 동치

DFA 최소화는 어떤 접미사에 대해서도 같은 수용 결과를 내는 상태를 합친다. 수용 토큰 종류와 우선순위가 다르면 단순히 둘 다 수용 상태라는 이유로 합칠 수 없다. **관련 장:** 11장.

## Dragon Book의 통합적 컴파일러 모델

Aho·Lam·Sethi·Ullman의 교재는 언어 이론, 구문 분석, 구문 지향 번역, 데이터 흐름, 코드 생성까지 고전적 컴파일러 과정을 체계화한다. 용어와 알고리즘의 공통 기준점 역할을 한다. **관련 장:** 60장.

## FIRST, FOLLOW, nullable

FIRST(α)는 α에서 시작할 수 있는 터미널 집합, nullable(α)는 α⇒*ε 여부, FOLLOW(A)는 어떤 문장형에서 A 바로 뒤에 올 수 있는 터미널 집합이다. 예측 Parser와 SLR reduce 조건의 기반이다. **관련 장:** 17장, 19장, 21장.

## GCC Internals의 산업적 진화

GCC Internals는 프런트엔드 등록, tree/GIMPLE, SSA, RTL, machine description, pass manager, 진단·디버그 훅을 문서화한다. 오랜 이식 역사에서 축적된 설계 층위를 보여준다. **관련 장:** 63장.

## GCC의 프런트엔드–GIMPLE–RTL 구조

GCC는 여러 언어 프런트엔드가 GENERIC과 GIMPLE 계열 표현을 거쳐 RTL 및 대상 기계 설명으로 내려가는 다언어·다대상 컴파일러 체계다. 드라이버는 전처리기, 컴파일러 본체, 어셈블러, 링커를 조정한다. **관련 장:** 3장, 63장.

## IR 검증기와 JIT 실행

검증기는 타입, SSA dominance, CFG, phi, 호출 시그니처 같은 구조 조건을 검사한다. JIT는 메모리 안의 IR을 최적화·코드 생성·재배치해 즉시 호출 가능한 주소로 만든다. **관련 장:** 31장, 33장, 47장, 54장, 62장.

## LALR 상태 병합과 충돌

LALR은 동일한 LR(0) core를 가진 LR(1) 상태의 lookahead를 합쳐 상태 수를 줄인다. 전통적인 Parser 생성기에서 널리 사용된다. **관련 장:** 22장.

## LL(1) 예측 분석

LL(1)은 입력을 왼쪽에서 읽고 좌측 유도를 구성하며 한 토큰 lookahead로 규칙을 선택하는 문법·알고리즘 계열이다. **관련 장:** 19장.

## LLVM Backend의 lowering 계층

LLVM 백엔드는 IR을 대상 독립 legalization, instruction selection, Machine IR 최적화, register allocation, scheduling, MC emission을 거쳐 어셈블리 또는 객체로 만든다. **관련 장:** 49장, 54장, 58장, 66장.

## LLVM C++ API와 IRBuilder

LLVM C++ API는 Context가 타입과 상수를 소유하고 Module이 전역 단위를, Function과 BasicBlock이 CFG를, IRBuilder가 삽입 위치와 명령 생성을 관리하는 계층을 제공한다. **관련 장:** 33장, 47장, 66장.

## LLVM IR의 타입과 명령

LLVM IR은 정수 폭, 부동소수, 벡터, 배열, 구조체, 포인터, 함수 타입을 명시하고 대부분의 계산 명령이 SSA 값을 생성한다. 메모리 효과는 load/store/call 등으로 드러난다. **관련 장:** 31장, 46장.

## LLVM 논문의 설계 주장과 현재적 해석

LLVM 초기 논문은 수명 전체 프로그램 분석을 위한 저수준 가상 명령 집합과 컴파일러 인프라를 제안했다. SSA, 타입 정보, 영속적 IR, 링크 시·런타임 최적화가 핵심 주장이다. **관련 장:** 62장.

## LLVM 설치와 버전 고정

LLVM 도구체인은 패키지 설치, 공식 바이너리, 소스 빌드 중 하나로 준비한다. 책의 명령은 `clang`, `opt`, `llc`, `llvm-as`, `llvm-dis`가 같은 주요 버전에 속한다는 전제를 둔다. **관련 장:** 45장.

## LLVM의 라이브러리형 컴파일러 인프라

LLVM은 강한 타입을 가진 SSA 기반 IR, 재사용 가능한 분석·변환 라이브러리, 다수의 백엔드와 도구를 제공한다. Clang은 C 계열 프런트엔드이며 LLVM 자체와 동일 개념은 아니다. **관련 장:** 4장, 62장, 63장.

## LR 항목, closure, goto

LR Parser는 지금까지 읽은 viable prefix와 앞으로 기대하는 문맥을 상태에 요약한다. 점이 있는 생산 규칙 A→α·β가 LR 항목이다. **관련 장:** 21장.

## Lexer–Parser–AST 통합

프런트엔드 통합의 핵심은 토큰 종류, 소스 범위, 오류 복구, AST 불변식이 단계 사이에서 일관되게 유지되는 것이다. 한 단계의 임시 편법이 다음 단계의 복잡도로 전가된다. **관련 장:** 51장, 56장.

## MiniLang 언어 사양과 실행 의미

MiniLang은 변수, 함수, if, while, C형 for, return, 고정 배열, UTF-8 문자열, 구조체를 제공하는 정적 타입 교육용 언어다. 사양은 문법뿐 아니라 평가 순서, scope, 값 전달, 오류를 포함한다. **관련 장:** 50장.

## MiniLang 의미 분석과 값 모델

MiniLang의 변수는 어휘 scope에 속하고, 구조체와 고정 배열 매개변수는 값 의미로 전달된다. 함수 반환은 교육용 ABI를 단순화하기 위해 scalar 또는 void로 제한한다. **관련 장:** 52장, 57장.

## MiniLang 최적화 파이프라인

교육용 최적화기는 먼저 immutable AST에서 상수 폴딩, 조건 분기 단순화, return 뒤 문장 제거를 수행하고, 별도 연구실 IR에서 지배·SSA·활성·레지스터 할당을 구현한다. **관련 장:** 34장, 53장, 57장.

## Modern Compiler Implementation의 구현 중심 접근

Appel의 시리즈는 Tiger 언어를 따라 프런트엔드, 프레임, IR tree, canonicalization, instruction selection, liveness, graph-coloring allocation을 실제 구현 흐름으로 연결한다. **관련 장:** 61장.

## Pratt Parser와 binding power

Pratt Parser는 토큰의 prefix parse 함수와 infix/postfix binding power를 결합해 다양한 표현식 문법을 작은 루프로 분석한다. **관련 장:** 20장.

## Python으로 구현하는 참조 Lexer

Python Lexer는 빠른 구현과 명확한 진단에 유리해 언어 사양의 실행 가능한 기준으로 적합하다. dataclass, Enum, Unicode 문자열을 이용하면 구조가 간결하다. **관련 장:** 16장, 51장.

## RISC-V의 모듈형 ISA

RISC-V는 작은 기본 정수 ISA에 곱셈, 원자, 부동소수, 벡터, 압축 명령 확장을 조합한다. 명령 형식과 확장 명세가 공개되어 교육용 백엔드에 적합하다. **관련 장:** 44장.

## Rust로 구현하는 안전한 Lexer

Rust Lexer는 `&str`의 유효 UTF-8 보장, enum 기반 토큰, 빌림을 이용해 소스 슬라이스를 복사 없이 전달할 수 있다. 바이트 인덱스가 문자 경계인지 반드시 보장해야 한다. **관련 장:** 15장, 16장, 64장.

## SSA 값, phi, 메모리 모델

LLVM의 가상 레지스터 값은 한 번만 정의되지만 메모리는 load/store로 갱신된다. phi는 블록 진입 간선에 따라 서로 다른 SSA 값을 하나로 선택한다. **관련 장:** 32장.

## Shift–Reduce 실행 모델

Shift–reduce Parser는 상태 스택과 값 스택을 유지하며 입력 토큰을 shift하거나 생산 규칙의 우변을 reduce한다. accept와 error가 나머지 action이다. **관련 장:** 21장, 22장.

## Thompson 구성과 ε-NFA

Thompson 구성은 정규 표현식의 구조를 따라 작은 NFA 조각을 합성한다. 각 조각은 하나의 진입과 하나의 이탈을 가지므로 선택·연결·반복을 국소적으로 구현할 수 있다. **관련 장:** 10장.

## Visitor Pattern과 이중 디스패치

Visitor는 닫힌 노드 계층에 새로운 연산을 추가할 때 각 노드가 방문자 메서드를 호출하게 하는 패턴이다. 프린터, 타입 검사, 코드 생성 같은 연산을 노드 정의와 분리한다. **관련 장:** 25장.

## `define i32 @main()` 해부

LLVM 함수 정의는 linkage·호출 규약·반환 타입·이름·매개변수·속성과 기본 블록 본문으로 구성된다. `define i32 @main()`은 인수 없는 i32 반환 함수 정의의 최소 형태다. **관련 장:** 31장, 47장.

## getelementptr와 데이터 레이아웃

GEP는 메모리를 읽지 않고 집계 타입 안의 주소를 계산한다. 인덱스는 바이트 오프셋이 아니라 타입 구조를 따라가며 target DataLayout이 실제 크기와 정렬을 결정한다. **관련 장:** 32장, 54장.

## x86 32비트의 CISC 특성과 제약

x86은 가변 길이 명령, 풍부한 addressing mode, EFLAGS, 제한적인 전통 레지스터를 가진 CISC ISA다. 32비트 환경은 레지스터 압박과 여러 ABI 변형을 이해하는 데 유용하다. **관련 장:** 41장.

## x86-64 레지스터와 호출 규약

x86-64는 16개 범용 레지스터, RIP-relative 주소, 확장된 인코딩을 제공한다. System V AMD64와 Windows x64 ABI는 인수 레지스터, shadow space, red zone, 보존 레지스터에서 다르다. **관련 장:** 8장, 39장, 42장, 44장.

## ε-closure와 NFA 실행

ε-closure(S)는 입력을 소비하지 않고 S에서 도달 가능한 모든 상태 집합이다. NFA 실행은 현재 closure에서 문자 전이를 적용한 뒤 다시 closure를 취하는 반복이다. **관련 장:** 10장, 11장.

## 객체 파일, ABI, 정적·동적 링크

객체 파일은 코드와 데이터뿐 아니라 섹션, 심볼, 재배치, 디버그 정보, 예외 메타데이터를 담는 컨테이너다. ABI는 별도 컴파일된 구성 요소가 바이너리 수준에서 협력하는 규칙이다. **관련 장:** 8장, 40장, 41장, 42장, 43장, 46장, 58장, 67장.

## 구문 설탕 제거와 핵심 언어

desugaring은 `for`, 복합 대입, 패턴 같은 편의 문법을 더 작은 핵심 구문으로 변환한다. 이후 패스가 처리해야 할 노드 종류를 줄인다. **관련 장:** 23장, 24장.

## 구문 오류 복구

오류 복구의 목표는 가능한 한 정확한 첫 진단을 내고, 무한 루프 없이 다음 독립 구문까지 진행해 추가 유용한 진단을 수집하는 것이다. **관련 장:** 18장, 19장, 22장, 56장.

## 다중 의미 오류와 poison 전파

의미 분석은 한 파일에서 여러 독립 오류를 찾되 첫 오류로 생긴 가짜 오류를 억제해야 한다. ErrorType과 InvalidSymbol은 실패를 값으로 표현하는 poison 역할을 한다. **관련 장:** 27장, 28장, 29장, 52장.

## 데이터 흐름 분석 프레임워크

데이터 흐름 분석은 CFG 각 지점의 사실을 격자 값으로 표현하고 전이 함수와 meet 연산의 고정점을 계산한다. 도달 정의, 활성 변수, 상수 전파가 같은 틀을 공유한다. **관련 장:** 7장, 35장, 36장, 37장, 38장, 39장, 48장, 60장.

## 도달 불능 코드와 죽은 정의 제거

Dead Code Elimination은 실행 결과에 영향을 주지 않는 명령이나 블록을 제거한다. 도달 불능 블록 제거와 결과가 사용되지 않는 순수 명령 제거는 관련되지만 다른 분석을 사용한다. **관련 장:** 35장, 53장, 65장.

## 런타임 ABI와 내장 함수

언어의 출력, 문자열, 경계 오류, 할당, 패닉은 생성 코드와 런타임 사이의 ABI로 연결된다. 이 계약은 함수 이름뿐 아니라 타입, 소유권, 오류 종료 규칙을 포함한다. **관련 장:** 32장, 54장, 58장, 66장.

## 레지스터 할당, 간섭, spill

레지스터 할당은 무한한 가상 레지스터를 제한된 물리 레지스터와 스택 슬롯에 배치한다. 동시에 살아 있는 값은 같은 레지스터를 공유할 수 없다. **관련 장:** 37장, 39장, 41장, 43장, 49장, 61장.

## 링킹, 심볼, 재배치

컴파일된 객체 파일의 주소는 대개 최종적이지 않다. 링커는 여러 객체의 섹션을 배치하고 심볼 정의와 참조를 연결하며, 재배치 항목에 따라 명령과 데이터의 주소 필드를 수정한다. **관련 장:** 3장, 8장, 42장.

## 명령 집합과 추상 기계

백엔드는 IR 연산을 대상 ISA의 레지스터, 메모리, 명령 인코딩, 조건 코드 모델로 낮춘다. ISA는 마이크로아키텍처와 다르며 같은 ISA도 성능 특성이 크게 다를 수 있다. **관련 장:** 8장, 39장, 40장, 41장, 43장, 49장, 60장.

## 모호성, 결합성, 우선순위

하나의 토큰열에 둘 이상의 파스 트리가 존재하면 문법은 모호하다. 산술식의 연산자 우선순위와 dangling else가 대표적이다. **관련 장:** 17장, 19장, 20장, 21장, 22장.

## 문맥 자유 문법과 유도

문맥 자유 문법은 비단말 하나를 기호열로 바꾸는 생성 규칙으로 중첩 구조를 표현한다. 프로그램의 문장과 표현식 구조는 대체로 CFG로 기술된다. **관련 장:** 6장, 17장, 18장, 60장.

## 배열·문자열·구조체 타입

배열은 원소 타입과 길이, 구조체는 이름 붙은 필드 순서, 문자열은 언어가 정한 불변성·인코딩·길이 모델을 포함한다. 표면 타입과 ABI 레이아웃을 구분해야 한다. **관련 장:** 28장, 32장, 50장.

## 부분집합 구성법

부분집합 구성은 NFA 상태 집합 하나를 DFA 상태 하나로 해석한다. DFA는 각 입력 클래스마다 다음 상태가 하나이므로 실행 시 상태 집합 관리가 필요 없다. **관련 장:** 11장.

## 부트스트래핑과 자기 호스팅

자기 호스팅 컴파일러는 자신이 구현하는 언어로 작성된 컴파일러다. 최초 버전은 다른 언어 또는 기존 컴파일러로 빌드해야 하므로 신뢰의 사슬과 단계적 부트스트랩이 필요하다. **관련 장:** 2장.

## 상수 폴딩과 대수 단순화

상수 폴딩은 피연산자가 컴파일 시 알려진 연산을 계산하고, 대수 단순화는 항등식으로 표현을 줄인다. 둘 다 언어의 정수 오버플로, 부동소수 NaN, 평가 순서를 존중해야 한다. **관련 장:** 7장, 34장, 53장.

## 새 Pass Manager와 분석 보존

LLVM의 새 Pass Manager는 모듈·CGSCC·함수·루프 분석 관리자를 분리하고, 변환 패스가 어떤 분석 결과를 보존하는지 명시하게 한다. **관련 장:** 48장, 62장, 66장.

## 세 주소 코드와 기본 블록 CFG

세 주소 코드는 한 명령이 대체로 하나의 연산과 명시적 결과를 갖게 해 데이터 의존을 드러낸다. 기본 블록은 중간 진입 없이 순차 실행되는 최대 명령열이며 terminator가 후속 블록을 정한다. **관련 장:** 7장, 30장, 31장, 35장, 36장.

## 소스 위치와 범위 추적

소스 위치는 바이트 오프셋, 행, 열, 파일 식별자를 연결한다. UTF-8에서는 바이트 수, Unicode scalar 수, 화면 열이 서로 다르므로 내부 표현과 표시 규칙을 구분해야 한다. **관련 장:** 5장, 12장, 13장, 15장, 18장, 23장, 26장.

## 심볼 테이블과 식별자 interning

심볼 테이블은 이름을 선언 정보에 연결한다. 선언 종류, 타입, 저장 위치, 가시성, 소스 범위를 저장하며 scope 구조를 반영한다. **관련 장:** 26장, 27장, 65장.

## 어휘 범위와 이름 해석

어휘 범위에서는 이름의 의미가 소스의 정적 중첩 구조로 결정된다. 블록 진입 시 scope를 push하고 이탈 시 pop하면 가장 가까운 선언을 찾을 수 있다. **관련 장:** 26장, 27장, 52장.

## 원시 언어와 대상 언어

원시 언어는 사용자가 작성하는 추상 수준의 규칙 집합이고, 대상 언어는 컴파일 결과가 따르는 실행 또는 교환 형식이다. 대상은 기계어뿐 아니라 어셈블리, 바이트코드, C, WebAssembly, LLVM IR도 될 수 있다. **관련 장:** 1장.

## 인라인 확장과 비용 모델

인라이닝은 호출 위치에 피호출 함수의 본문을 복제해 호출 비용을 없애고 상수 전파·DCE 기회를 연다. 그 자체보다 후속 최적화가 주된 이익일 때가 많다. **관련 장:** 38장.

## 입력 버퍼와 문자 디코딩

Scanner의 성능은 문자 분류보다 입력 접근과 경계 검사에 좌우되는 경우가 많다. 전체 파일 매핑, 슬라이딩 버퍼, 스트리밍 입력은 서로 다른 지연과 메모리 특성을 가진다. **관련 장:** 12장, 13장, 14장.

## 자연 루프, LICM, 귀납 변수

후퇴 간선 n→h에서 h가 n을 지배하면 h는 자연 루프 헤더다. Loop-Invariant Code Motion은 반복마다 같은 순수 계산을 preheader로 옮긴다. **관련 장:** 38장.

## 재귀 하강 Parser

재귀 하강 Parser는 비단말마다 함수를 두고 토큰 lookahead에 따라 생산 규칙을 선택한다. 호출 구조가 문법 구조와 닮아 진단과 AST 생성 로직을 직접 제어하기 쉽다. **관련 장:** 18장, 20장, 51장, 64장.

## 재타기팅과 모듈성

재타기팅은 새로운 CPU, 운영체제, 객체 형식 또는 ABI에 컴파일러를 적용하는 능력이다. 재타기팅 가능성은 프런트엔드가 기계 세부사항을 얼마나 격리하는지에 좌우된다. **관련 장:** 2장, 3장, 4장, 44장, 45장, 49장.

## 정규 언어의 폐쇄성과 한계

정규 언어는 합집합, 교집합, 여집합, 연결, 반복 등 여러 연산에 대해 닫혀 있어 토큰 규칙의 조합과 제외를 체계적으로 다룰 수 있다. 유한한 메모리로 인식 가능하다는 점이 핵심이다. **관련 장:** 9장, 11장.

## 정규 표현식의 대수

정규 표현식은 리터럴, 합집합, 연결, Kleene star를 기본 연산으로 하는 정규 언어의 표기다. 프로그래밍 언어의 토큰 패턴은 대체로 정규 언어이므로 Lexer 명세에 적합하다. **관련 장:** 9장, 10장.

## 정적 단일 대입(SSA)

SSA에서는 각 변수 버전이 정확히 한 번 정의되고 모든 사용은 하나의 정의를 가리킨다. 제어 흐름 합류에서 phi가 간선별 값을 선택한다. **관련 장:** 37장, 57장, 65장.

## 정확성, 안전성, 결정성

정확성은 올바른 입력의 의미를 보존하고 잘못된 입력을 정해진 진단으로 거부하는 성질이다. 안전성은 컴파일러 자체가 충돌하거나 메모리를 훼손하지 않는 성질이고, 결정성은 동일 입력과 옵션이 동일 산출물을 만드는 성질이다. **관련 장:** 1장, 2장, 4장, 10장, 14장, 17장, 26장, 29장, 30장, 33장, 35장, 36장, 40장, 45장, 47장, 48장, 55장, 57장, 59장.

## 중간 표현의 추상화 수준

IR은 분석과 변환을 위해 프로그램 의미를 명시적으로 재구성한 언어다. 트리, DAG, 세 주소 코드, SSA, CPS, 기계 IR은 서로 다른 질문에 적합하다. **관련 장:** 7장, 30장, 61장.

## 지배 관계와 지배 경계

entry에서 블록 b로 가는 모든 경로가 d를 지나면 d가 b를 지배한다. 즉시 지배자는 b를 엄격히 지배하는 가장 가까운 블록이며 지배 트리를 이룬다. **관련 장:** 36장, 37장, 38장.

## 직접 x86-64 기계어 생성

직접 기계어 생성기는 어셈블러를 거치지 않고 opcode, REX, ModR/M, immediate를 바이트로 인코딩한다. 작은 산술식 컴파일러는 백엔드의 마지막 단계를 투명하게 보여준다. **관련 장:** 40장, 42장, 58장, 67장.

## 진단을 컴파일러의 공개 API로 보기

진단은 부가 기능이 아니라 사용자가 언어 규칙을 이해하는 주 인터페이스다. 좋은 진단은 위치, 문제, 원인, 기대값, 수정 방향을 구분하고 후속 오류를 억제한다. **관련 장:** 5장, 6장, 13장, 29장, 33장.

## 차등 테스트와 언어 간 동등성

차등 테스트는 독립 구현들이 같은 입력에 대해 같은 결과를 내는지 비교한다. 정답을 직접 계산하기 어려운 컴파일러 구성 요소에서 강력한 오류 탐지 방법이다. **관련 장:** 15장, 16장, 25장, 53장, 56장, 59장.

## 최장 일치와 규칙 우선순위

Scanner는 현재 위치에서 가능한 토큰 중 가장 긴 문자열을 선택하는 최장 일치 원칙을 주로 사용한다. 길이가 같으면 명세 순서나 명시적 우선순위로 결정한다. **관련 장:** 9장, 12장, 14장.

## 컴파일 파이프라인과 단계 경계

컴파일 과정은 토큰, 구문 트리, 타입이 붙은 AST, 중간 표현, 기계 코드, 객체 파일이라는 연속된 계약으로 구성된다. 단계 이름보다 중요한 것은 각 단계가 무엇을 입력으로 받고 어떤 불변식을 보장하는지다. **관련 장:** 5장, 46장.

## 컴파일과 해석의 연속체

컴파일과 해석은 상호 배타적인 분류가 아니다. 인터프리터도 토큰화와 AST 생성을 수행하고, JIT 컴파일러는 실행 중 프로파일을 이용해 일부 코드를 기계어로 바꾸며, AOT 컴파일러도 링크 시점과 적재 시점에 추가 변환을 거친다. **관련 장:** 1장, 2장.

## 컴파일러의 의미 보존 계약

컴파일러는 원시 프로그램을 다른 표현으로 바꾸는 변환기이지만, 핵심 계약은 단순한 텍스트 변환이 아니라 관찰 가능한 동작의 보존이다. 입력, 출력, 종료 상태, 예외, 메모리 효과처럼 언어 사양이 관찰 가능하다고 정한 현상을 기준으로 보존 범위를 정한다. **관련 장:** 1장, 34장, 50장.

## 타입 판단과 규칙 기반 검사

타입 검사는 표현식이 어떤 연산을 허용하는지 정적 규칙으로 판단한다. 환경 Γ 아래 식 e가 타입 τ를 갖는다는 판단을 Γ⊢e:τ로 쓴다. **관련 장:** 6장, 28장, 34장, 52장, 65장.

## 테스트 피라미드, 퍼징, 디버깅

컴파일러 테스트는 토큰·Parser 함수 단위 테스트, 단계별 golden, 전체 실행, 차등 테스트, fuzzing, 다중 타깃 CI를 계층화한다. 오류 입력은 정상 입력만큼 중요하다. **관련 장:** 45장, 48장, 55장, 59장, 67장.

## 토큰 모델과 값 표현

토큰은 종류, 원문 범위, 선택적 해석 값으로 구성된다. 식별자 원문, 정수 값, 문자열 디코딩 값, 주석 보존 여부를 명시해야 Parser와 포매터 요구를 동시에 충족한다. **관련 장:** 6장, 9장, 12장, 13장, 15장.

## 프런트엔드·미들엔드·백엔드의 책임 분리

프런트엔드는 언어 사양을 이해하고, 미들엔드는 언어와 기계 사이의 공통 의미를 최적화하며, 백엔드는 대상 명령어와 ABI 제약을 만족시킨다. 이 경계는 조직 구조가 아니라 정보 책임의 경계다. **관련 장:** 3장, 5장, 30장, 55장.

함수 타입은 매개변수 타입 순서, 반환 타입, 호출 규약, 가변 인자 여부, 효과 속성을 포함한다. 호출은 인수 개수와 각 타입이 시그니처에 맞아야 한다. **관련 장:** 27장, 28장, 29장, 50장.
